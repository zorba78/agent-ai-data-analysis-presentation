## 3. 행동 규칙

1. 가정을 숨기지 않는다. 구현 전에 가정을 밝히고, 불확실하면 묻는다
2. 여러 해석이 가능하면 하나를 조용히 고르지 않고 해석들을 제시한다
3. 여러 단계 작업은 "단계 → 검증: 확인 방법" 형식의 짧은 계획을 먼저 낸다
   - 사례: "1. 공군 자료 정제 → 검증: 남성 n = 2,739, 제외 88 로그 확인"
4. 분석계획서(`docs/analysis-plan.md`)를 먼저 확정한다. 정의, 포함과 제외 기준, 공변량, 모형을 분석 전에 적는다
5. 요청받은 것만 구현한다. 요청하지 않은 기능, 옵션, 추가 분석을 넣지 않는다
6. 결과 숫자는 반드시 실행한 코드의 출력에서 가져온다. 추정하거나 기억으로 쓰지 않는다
7. 모든 결과는 점추정과 95% 신뢰구간으로 말한다. p값만 따로 보고하지 않는다. 다중 비교는 탐색적임을 밝힌다
8. 통계적 유의성을 "증명"으로 쓰지 않는다. <여기에: 연구 설계의 한계. 사례: 단면 연구의 인과 추론 한계를 항상 밝힘>

## 4. 코딩 규칙

- 언어와 환경: <여기에: 사례: R 4.6.1이 주 분석 도구(haven, survey, tidyverse, gtsummary, flextable). Python은 자료 탐색과 파일 변환에만 사용. 같은 결과를 두 언어로 중복 구현하지 않음>
- 새 패키지는 사유를 말하고 승인을 받은 뒤 설치한다
- 스크립트는 프로젝트 폴더 맨 위에서 `Rscript <경로>`로 실행할 수 있어야 한다. `setwd()` 금지, 경로는 상대 경로
- 스크립트 머리에 목적, 입력, 출력, 작성자와 날짜를 적는다

  ```r
  # 01_clean_airforce.R
  # Purpose : Clean pilot dataset, restrict to men, recompute MetS
  # Input   : data/rawdata/<file>
  # Output  : data/derived-data/01_af_clean.rds, output/logs/01_flow.csv
  # Author  : <agent name or user>, <YYYY-MM-DD>
  set.seed(2022)
  ```

- 모든 스크립트는 성공 기준을 가진다. 기대 표본 수, 기대 범위, 교차 검증표 중 하나 이상을 `stopifnot()`으로 확인하고 로그에 남긴다

  ```r
  stopifnot(nrow(af_m) == 2739, all(af_m$SEX == 1))
  ```

- 스크립트 끝에서 `sessionInfo()`를 로그 파일로 저장한다
- 표와 그림은 손으로 고치지 않는다. 코드를 다시 실행하면 그대로 나와야 한다
- 요청과 직접 연결된 줄만 바꾼다. 옆의 코드, 주석, 서식을 "개선"하지 않는다

## 5. 윤리 제약과 민감 데이터

- 만들어 내거나 추측하지 않는다. 모든 진술은 확인할 수 있는 출처에 근거하고, 불확실하면 "확인할 수 없습니다"라고 쓴다
- 참고문헌은 PMID 또는 DOI가 확인되는 문헌만 쓴다
- 원자료(`data/rawdata/`)는 절대 수정하지 않는다. 덮어쓰기, 삭제, 이동 금지
- 산출물에 개인 단위 자료를 드러내지 않는다. `head()`, `print(df)`, `View()` 금지. 구조는 `str()`, `summary()`, 집계표로 본다
- 집계값만 보고한다. 5 미만 셀은 감춘다
- 식별 가능 변수(<여기에: 예: 등록번호, 검진일, 소속>)는 읽지 않고 출력하지 않는다
- 데이터를 외부 서비스에 올리지 않는다
