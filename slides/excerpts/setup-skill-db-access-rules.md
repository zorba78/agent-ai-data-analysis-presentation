# setup-skill-db-access-rules

원본: healthy-aging-project-annual-report/.claude/skills/<db>-db/SKILL.md "지킬 것" 절 (마스킹 완료, 2026-10-19. 스킬 이름에 DB명이 들어 있어 본문에서는 `<db>-db`로 쓴다. 파일명은 지정받은 그대로)
섹션: 9
보여줄 이유: 임상 DB에 에이전트를 붙일 때의 보안 규칙 7개. 읽기만, 집계값만, 5 미만, 접속정보 파일은 Read로도 열지 않음

```markdown
## 지킬 것
1. **읽기만 한다.** `SELECT`, `SHOW`, `DESCRIBE` 만 실행한다. DB 에 쓰거나 구조를 바꾸는 문장은 실행하지 않는다. 세션을 열면 먼저 `SET SESSION TRANSACTION READ ONLY` 를 실행한다.
2. **집계값만 꺼낸다.** 행 수, 대상자 수, 결측률, 분포 요약처럼 개인을 특정할 수 없는 값만 조회해 기록한다. 행 단위 자료를 대화, `drafts/`, `output/` 에 옮기지 않는다.
3. **식별 가능 정보는 조회 결과에 넣지 않는다.** `<table>.<column>`(생년월일), `<table>.<column>`(이름 초성), 개별 `<id-column>`·`<id-column>` 값이 해당한다. 집계할 때 5명 미만인 칸은 "5 미만"으로 적는다.
4. **접속 정보를 옮겨 적지 않는다.** 계정과 비밀번호는 `<env-file>` 에만 둔다. 이 파일을 `Read` 로 열지 않고, 문서·초안·메모리·명령줄에 값을 쓰지 않는다. 스크립트가 실행 중에 직접 읽게 한다.
5. **범위를 넓히지 않는다.** 같은 계정으로 다른 데이터베이스(`<db>`, `<db>`, `<db>`, `<db>` 등 다른 과제 자료로 보임)도 보이지만 `<db>`, `<db>` 만 조회한다.
6. **무거운 조회는 피한다.** 서버 버퍼풀이 128 MB 라 큰 스캔 하나가 다른 사용자에게 영향을 준다. 모든 조회에 `/*+ MAX_EXECUTION_TIME(15000) */` 힌트를 붙인다.
   특히 `<table>`(N억 행)은 `<id-column>` 조건 없이 조회하지 않는다(`<column>` 에 인덱스가 없어 전체 스캔이 된다). `<table>`(N백만 행), `<table>`(N백만 행)도 기본 키 조건 없이 집계하지 않는다.
7. 이 계정은 서버 전체 관리 권한(`ALL PRIVILEGES`, `SUPER` 등)을 가진 계정이다. 그래서 더 조심한다. DDL·DML 문장은 어떤 경우에도 실행하지 않는다.
```
