에이전트 방식

1. AI 활용 방식

  • 대본
    • 제 PC의 Positron 창 하나 안에서 Claude Code가 네 칸과 연결됩니다.
    • 챗봇과 다른 점은 실행, 파일, 기억 세 가지입니다.
    • 실행, Claude Code가 제 R 세션에서 코드를 돌리고 에러를 읽고 고칩니다.
    • 파일, 코드와 표와 원고가 레포에 날짜별로 남습니다.
    • 기억, CLAUDE.md와 memory를 다음 세션이 다시 읽습니다.
    • 주황 칸 CLAUDE.md는 사람이 쓰는 자리이고, 이후 장에서도 같은 색입니다.
    • 오른쪽 위 Claude 모델에는 원자료 파일이 아니라 읽은 내용, 출력, 지시가 갑니다.
    • 계산은 제 PC의 R이 전체 데이터로 하고, 모델에는 결과 텍스트만 갑니다.
    • 다만 head(), print(df) 같은 출력은 관측치가 그대로 넘어갑니다.
    • 그래서 CLAUDE.md에 집계만 출력하고 행 출력 함수는 쓰지 말라고 적습니다.
    • 그 규칙을 지켰는지는 제가 출력을 보고 확인합니다.
    • 오른쪽 아래 MCP 문헌 검색은 검색 질의만 밖으로 나갑니다.
    • 이 발표 전체가 이 그림의 설명입니다.
    • 먼저 이 구조로 하는 연구 작업을 단계로 나눠 보겠습니다.
  • 메모
  • 시간: 2분
  • 챗봇과의 차이 세 가지: 실행, 파일, 기억
  • 실행: 에이전트가 내 R 세션에서 코드를 돌리고 에러를 읽고 고침
  • 파일: 코드, 표, 원고가 레포에 날짜별로 남음
  • 기억: CLAUDE.md와 memory/를 다음 세션이 다시 읽음
  • 주황 칸 = 사람이 쓰는 자리. 이후 모든 장에서 같은 색
  • 오른쪽 위 Claude 모델: 추론은 Anthropic 서버. 원자료 파일 업로드는 없지만 에이전트가 읽은 내용, 명령 출력, 내 지시는 전송됨
  • 청중 질문 대비: “구조와 집계를 보려면 LLM이 데이터를 다 읽는 것 아닌가”. 아님. 두 단계로 나뉨
    • 1단계: 에이전트가 쓴 코드를 내 PC의 R이 실행. R이 전체 데이터를 읽고 전체 관측치로 계산. 전부 내 PC 안
    • 2단계: LLM에게 가는 것은 실행 결과 텍스트뿐. nrow()는 숫자 하나, table()은 집단별 개수 몇 줄. 데이터 객체는 가지 않음
    • 예: 유병률 45.3%는 3,697명 중 누구의 값도 LLM이 보지 않고 받는 결과. 사람이 콘솔에서 summary() 결과만 읽는 것과 같음
  • 관측치가 전송되는 경우: head(), print(df), glimpse() 출력 / 데이터 파일을 Read 도구로 직접 열 때 / 에러 메시지에 값이 섞일 때 / 5명 미만 셀의 집계
  • 그래서 CLAUDE.md 규칙: 집계만 출력, 행 출력 함수 금지, 데이터 파일 직접 열기 금지, 작은 셀은 “5 미만”. 규칙은 에이전트가 지킬 때만 작동, 지켰는지는 사람이 출력을 보고 확인(3막 ② 탐색)
  • 그래서 집계만 출력하게 하는 규칙이 필요(3막 ② 탐색, CLAUDE.md)
  • 오른쪽 아래 MCP: 문헌 검색 질의만 밖으로

    • 계보: R Markdown(2012)은 R 패키지 rmarkdown + knitr. Quarto(2022)는 같은 팀이 만든 독립 실행 프로그램. Rmd 파일을 qmd로 바꾸지 않아도 Quarto가 그대로 렌더

    • 확장: Rmd에서 bookdown, xaringan, blogdown, distill로 나뉘던 기능이 Quarto 하나에 내장(책, 발표, 웹사이트, 상호참조, 탭, 콜아웃)
    • 문법: 청크 옵션을 #| echo: false 형식으로 청크 안에 YAML로 씀. 출력 형식별 옵션도 YAML 통일
    • 계속 지원: R Markdown도 유지보수는 계속됨. 새 기능은 Quarto에만 추가

  • 그림의 Quarto 아이콘은 공식 로고가 아니라 직접 그린 대체 아이콘(상표 사용 회피)

MCP: 개념과 역할

2. 작업 환경

개념

  • Model Context Protocol: 에이전트가 외부 도구를 함수처럼 부르는 규격
  • 서버 하나 = 도구 묶음 하나 (PubMed, R 세션)
  • 설정 한 번이면 모든 세션에서 사용

역할과 효과

  • Positron MCP: 내 R 세션에서 실행, 객체 조회
  • 문헌 MCP: 검색, 서지 조회, PDF 확보를 에이전트가 직접
  • 복사, 붙여넣기 단계가 없어짐
  • 결과에 DOI, 출처가 붙어 검증 가능

작성 요점

  • 무엇이 밖으로 나가는지 확인: 검색 질의만
  • 쓰는 도구만 연결. 많으면 선택이 흐려짐
  • 권한 allow에 도구 이름 단위로
  • 연결 상태 확인: claude mcp list
  • 대본
    • MCP는 에이전트가 외부 도구를 함수처럼 부르는 규격입니다.
    • Anthropic이 공개한 규격이고, 다른 에이전트도 지원합니다.
    • 서버 하나가 도구 묶음 하나로, PubMed 하나, R 세션 하나인 식입니다.
    • Positron MCP를 쓰면 에이전트가 돌린 코드가 제 콘솔에 그대로 찍힙니다.
    • 앞에서 같은 R 세션을 본다고 말씀드린 근거가 이것입니다.
    • 사례에서는 PubMed MCP로 문헌 24편의 서지를 조회했습니다.
    • 결과에 DOI와 출처가 붙어 와서 제가 검증할 수 있습니다.
    • 오른쪽 첫 요점처럼, 문헌 MCP로 밖에 나가는 것은 검색 질의입니다.
    • 다만 에이전트가 읽은 결과는 모델 서버로 간다는 점은 1막과 같습니다.
    • 연결 상태는 claude mcp list로 확인하고, 다음 장에서 사례의 구성을 보겠습니다.
  • 메모
  • 시간: 1.5분
  • 메시지 한 줄: 에이전트의 손을 늘리는 규격. 데이터는 안 나가고 질의만 나감
  • 개념: Anthropic이 공개한 규격, 다른 에이전트도 지원. 서버는 로컬 프로세스 또는 원격
  • 사례: 문헌 단계(3막 ⑤)에서 PubMed MCP로 24편 서지 조회, Europe PMC로 PDF. allow 항목에 lookup_article_by_citation, get_article_metadata
  • Positron MCP: 에이전트가 돌린 코드가 내 콘솔에 표시됨. 같은 세션을 본다는 것의 기술적 근거
  • 전송 범위: 문헌 MCP는 질의와 결과. 에이전트가 읽은 결과는 모델 서버로 감(1막 에이전트 방식 그림)

AI 활용 논문의 윤리

4. 정리

저자 자격

  • AI는 저자로 올릴 수 없음(ICMJE, COPE 공통)
  • 이유: 정확성, 무결성, 독창성에 책임질 수 없음
  • 저자 기준 4가지(기여, 초안 또는 수정, 최종 승인, 책임)를 AI는 못 채움
  • 감사의 글에도 AI를 사람처럼 적지 않음

사용 공개

  • 투고 시 커버레터에 사용 사실
  • 원고 해당 절에 도구 이름, 버전, 용도(예: 코드 작성, 문장 교정)
  • 문법 교정 수준은 면제하는 저널도 있음. 애매하면 공개
  • 저널마다 위치와 문구가 다름: 투고 규정 확인

최종 책임

  • AI 산출물은 틀리거나 빠지거나 치우칠 수 있음: 저자가 읽고 고침
  • AI 생성물을 1차 출처로 인용 불가. 인용은 원 문헌으로
  • 숫자는 실행 출력, 인용은 원문과 대조한 기록을 남김
  • 공개하지 않은 사용: 정정 대상, 경우에 따라 부정행위
  • 대본
    • 기준은 ICMJE 권고안이고, COPE도 2023년 2월 입장문에서 같은 방향을 냈습니다.
    • 첫 카드, AI는 저자 기준 네 가지를 채우지 못해 저자로 올릴 수 없습니다.
    • 두 번째 카드, 투고할 때 커버레터와 원고 해당 절에 도구 이름, 버전, 용도를 적습니다.
    • 위치와 문구는 저널마다 다르니 투고 규정을 먼저 보고, 애매하면 공개합니다.
    • 세 번째 카드, 숫자는 실행 출력과, 인용은 원문과 대조한 기록을 남깁니다.

    • 바탕: 모델은 토큰마다 후보 확률을 매기고 난수로 하나를 뽑음. 워터마크는 이 난수의 출처만 바꿈. 확률 자체는 손대지 않음
    • 시드 생성기: 비밀 키 + 직전 토큰 몇 개(슬라이딩 창, 논문 기본 4개)를 해시 → 시드. 같은 키, 같은 직전 토큰이면 같은 시드. 참조 구현은 Threefry 난수기, 63비트 키

    • 토너먼트 샘플링: 원래 분포에서 후보 여러 개 → 둘씩 짝지어 1층 g값 큰 쪽 승리(동점은 무작위) → 승자끼리 2층 g값으로 반복 → 참조 구현 기본 30층 → 최후 승자가 출력 토큰. 결과는 여전히 모델이 그럴듯하다고 본 후보 중 하나, g값 큰 쪽으로 살짝 기운 선택이 토큰마다 쌓임

    • 품질 보호 2, 반복 문맥 마스킹: 한 응답 안에서 같은 직전 토큰 묶음이 다시 나오면 같은 시드라 같은 방향으로 기울게 됨 → 그 토큰은 워터마크 없이 원래 분포로
    • 품질 보호 3, 적용 순서: temperature, top-k, top-p 조정이 끝난 분포에 적용. 사용자 샘플링 설정과 충돌 없음
    • 실증: DeepMind는 Gemini 응답 약 2천만 건 실험에서 사람 평가 품질 차이 없음. Anthropic 내부 시험도 내용, 창의성, 가독성 차이 없음, 토큰 증가 없어 비용 동일
    • 탐지: 모델 불필요, 키와 텍스트만. 토큰마다 직전 토큰 + 키로 시드와 g값 재계산 → g값 평균. 워터마크 없으면 0.5 근처, 있으면 0.5 초과 → 우연 확률 계산(참조 구현: 이항분포 p값, 또는 키별 학습한 베이즈 점수 0–1). 토큰이 많을수록 분산 줄어 확신 상승
    • 한계가 원리에서 나오는 이유: 짧은 글은 평균이 우연과 구분 안 됨 / 후보가 하나인 자리(Principia → Mathematica)는 고를 것이 없어 사실, 제목, 수치 많은 글에 희박 / 코드는 정확 출력 필요해 미적용, 주석만 / 편집은 고친 토큰과 그것을 문맥으로 쓰는 뒤 몇 토큰만 깨짐, 전면 재작성과 타 모델 패러프레이즈는 대부분 깨짐 / 사람 글 교정은 Claude가 고른 단어가 적음 / 탐지는 “이 키의 패턴이 있는가”만 답함
    • 키 관리: 키가 새면 누구나 넣거나 지울 수 있음 → 탐지는 API로만, 자격 기관 한정
    • 외부 검증: 2026-09 arXiv 논문(Nemecek 외), 공개 구현을 오픈 모델에 적용. 산문은 시드 변경 수준의 영향, 코드는 한 모델에서 정확도 3점 손실, 탐지는 우연 수준. 배포된 Claude 자체는 검증 불가라는 점을 거버넌스 문제로 지적
