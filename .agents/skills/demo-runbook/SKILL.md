# 시연 런북

시연은 사례 레포 `G:/Projects/airforce-fatty-liver`에서 사용자가 Positron으로 직접 한다. 이 스킬은 **대본과 점검표**를 만든다. 레포를 수정하지 않고, 분석을 다시 돌리지 않는다.

## 시연 3개 (AGENTS.md 구성 기준)

| 시연 | 섹션 | 형식 | 길이 | 내용 |
|---|---|---|---|---|
| D1 | 7 전처리, 코드 | 녹화 | 90초 (2–4배속 편집) | 에이전트가 세션 객체를 확인 → 코드 작성 → 에러 → 수정. 레포의 knit 실패 3원인 장면(finalize msg[19–21])을 모델로 한다 |
| D2 | 9 검증 | 녹화 | 60초 | "검증 보고서 써줘" → n, 결측, 변수 정의 점검표가 나오는 장면. `verify-numbers.R`을 돌리는 장면으로 대체 가능 |
| D3 | 10 표, 그림 | 라이브 | 3분 | Quarto 청크에서 `gtsummary` Table 1 렌더. 짧고 실패 위험이 낮다 |

녹화는 발표 전에 끝낸다. 라이브 D3는 실패 시 녹화본(D3 백업)으로 바로 넘어간다. 그러니 D3도 녹화해 둔다.

## `demo/runbook.md` 형식 (시연마다)

```markdown
## D1 <이름>

목적(청중이 봐야 할 것): 한 문장
시작 상태:
  - 레포 브랜치/커밋: ...
  - 열려 있는 파일, R 세션에 로드된 객체(이름만)
  - 에디터 글꼴 크기, 창 배치
입력 프롬프트(원문 그대로):
  > ...
기대 흐름: 1) ... 2) ... 3) ...
짚어줄 포인트(발표자가 말할 것): ...
걸리는 시간: 실측 __분 (녹화 원본) → 편집 후 __초
실패 모드와 대안:
  - 에이전트가 다른 경로로 가면: ...
  - 네트워크/한도: 녹화본으로 전환
녹화 파일: demo/clips/D1-<이름>.mp4
```

## 녹화 전 화면 노출 점검표 (AGENTS.md 화면 노출 규칙의 실행판)

녹화, 라이브 직전에 하나씩 확인하고 `demo/runbook.md` 끝의 점검표에 날짜와 함께 체크한다.

1. Positron 데이터뷰어: 열려 있으면 닫는다. 열어야 하면 ID, 검진일, 소속 열을 숨기고 요약 패널만 보인다.
2. R 콘솔 히스토리와 Variables 패널: 행 데이터를 출력한 흔적이 있으면 콘솔을 지운다(`Ctrl+L`).
3. 터미널 프롬프트의 경로: 사용자 홈 경로가 보이면 프롬프트를 짧게 바꾼다.
4. 환경변수, `.Renviron`, `.env`: 화면에 열리지 않게 탭을 닫는다. API 키가 있는 파일은 열지 않는다.
5. 에이전트 프롬프트에 "행 단위 출력 금지, 집계, 구조 출력만" 한 줄을 넣는다. 레포 CLAUDE.md에 이 규칙이 없으면 시연용 프롬프트에 직접 쓴다(레포는 수정하지 않는다).
6. 브라우저 탭, 알림, 메신저: 끈다.
7. 해상도 1920×1080, 에디터 글꼴 16pt 이상, 다크/라이트 테마는 슬라이드와 맞춘다.
8. 녹화 후: 클립을 끝까지 다시 보고 1–4번을 재확인한다. 하나라도 걸리면 그 구간을 잘라내거나 다시 찍는다.

## 편집 규칙

- 대기 구간(에이전트 응답 기다리는 시간)은 2–4배속 또는 점프컷. 입력하는 장면과 결과가 나오는 장면은 실속도.
- 자막으로 "지금 에이전트가 하는 일"을 한 줄씩. 자막 글꼴은 슬라이드와 같은 것.
- 클립 하나는 90초를 넘기지 않는다. 넘으면 두 클립으로 나누고 슬라이드도 둘로.
- 파일명: `demo/clips/D<번호>-<이름>.mp4`. 슬라이드에서는 `{{< video demo/clips/D1-knit-fix.mp4 >}}`.

## 하지 않는 것

- 레포의 분석을 다시 돌리거나 파일을 바꾸지 않는다.
- 연출된 실수를 넣지 않는다. 실제 로그에 있는 실수(두 OR 혼동, 척도 혼선, knit 실패)만 재현한다.
- 녹화 파일을 git에 넣지 않는다(`demo/clips/`는 `.gitignore`).
